I. Title of the Project

SARAS AI – Smart Assessment and Recognition Automation System: An AI-Powered Exam Answer-Sheet Evaluation and Marks Assessment System

II. Project Category

Artificial Intelligence / Machine Learning – Web Application (EdTech). The project combines Computer Vision, Optical Character Recognition (OCR), Natural Language Processing (NLP) and Large Language Models with a full-stack web application (React frontend, FastAPI backend).

III. Introduction

SARAS AI is a web application that reads scanned exam answer sheets, splits them into answers, and gives explainable first-pass marks against a teacher's rubric. The teacher reviews, corrects and approves every result.

a. Why?

  • Manual evaluation is slow – teachers spend many hours reading repetitive multi-page scripts, delaying results.
  • Marking is inconsistent – the same answer can receive different marks from different examiners or when the examiner is tired.
  • Students get little feedback – a bare number does not show which points were covered or missed.
  • Existing tools do not fit – OMR/MCQ systems cannot read written answers, and black-box AI graders give marks without evidence.

b. Importance

  • Reduces evaluation time and lets teachers focus on difficult or borderline answers.
  • Applies the same rubric to every student, improving fairness and consistency.
  • Gives evidence-based feedback: each key point is shown as matched, partial, missed or contradicted.
  • Keeps humans in control with a review queue, overrides and an audit log, which is essential for real exams.
  • Runs on low-cost hardware (a 4 GB laptop) and protects student privacy, making it practical for schools and colleges.

IV. Objective

  1. Automatically read scanned and handwritten answer sheets using image preprocessing and OCR.
  2. Segment each sheet into individual answers using the question numbers written by the student.
  3. Grade each answer against a rubric of weighted key points using NLP models, with explanations.
  4. Estimate a confidence score for every mark and route uncertain answers to the teacher.
  5. Provide a secure web interface for review, correction, approval, analytics and CSV export.
  6. Keep the system lightweight, private and deployable on modest hardware and the cloud.

V. Scope of the Project

In scopeDescriptive (written) answers in English; typed, scanned or photographed PDF answer sheets; rubric-based grading; teacher review and approval; results analytics and export; single-institution deployment.
UsersTeachers and examiners at schools, colleges and coaching institutes.
Out of scope (current version)Diagrams, mathematical derivations and drawings; regional-language answers; fully automatic marking without teacher approval.
Future scopeMultilingual OCR and grading, diagram evaluation, LMS integration, student feedback portal, larger-scale cloud deployment with persistent storage.

VI. Proposed Methodology

Rubric → Upload PDFs → Preprocessing → OCR → Segmentation → Grading → Confidence Routing → Teacher Review → Approval & Export

  1. Rubric creation – the teacher enters questions, maximum marks, a model answer and weighted key points, or drafts them automatically from an uploaded question paper.
  2. Upload – answer-sheet PDFs (up to 50 per batch) are validated for type, size and page count.
  3. Preprocessing – pages are rendered with PyMuPDF and cleaned with OpenCV: deskew, denoise, contrast enhancement (CLAHE) and thresholding.
  4. OCR – a cascade picks the best reader per page: PDF text layer, a vision-LLM reader, or the TrOCR handwriting model; unreadable pages are flagged for teacher transcription.
  5. Segmentation – the text is split into answers using question markers (e.g. "Q1", "Ans 2"), handling out-of-order and continued answers.
  6. Grading – each key point is checked with a DeBERTa-v3 Natural Language Inference model (ONNX, CPU) and a lexical scorer; an optional LLM marker (Groq / Gemini) adds a second opinion. Disagreements are flagged.
  7. Confidence routing – OCR, grading and segmentation confidences are combined and calibrated; confident answers are auto-accepted, uncertain ones go to the review queue.
  8. Teacher review – the teacher edits text, overrides marks with a reason, adjusts answer regions and approves sheets.
  9. Results – approved marks are shown in analytics (distribution, question difficulty) and exported as CSV.
  10. Evaluation – accuracy is measured with Quadratic Weighted Kappa, Cohen's κ, calibration error (ECE) and OCR error rates (CER/WER).

VIII. Conclusion

SARAS AI shows that AI can make answer-sheet evaluation faster, more consistent and more transparent without removing the teacher from the process. By combining image preprocessing, multi-engine OCR, key-point-based NLI grading and calibrated confidence routing, the system gives explainable marks and sends only uncertain cases for review. It runs on modest hardware, protects student data, and is already deployed as a working web application. With future work on multilingual support, diagram evaluation and larger real-world testing, it can become a practical tool for educational institutions.
